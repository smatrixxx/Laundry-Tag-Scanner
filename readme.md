# Laundry AI

Telegram-бот, который расшифровывает символы ухода на бирках одежды. Пользователь
присылает боту фото бирки — в ответ получает понятную инструкцию на русском языке:
что означают символы и как правильно стирать, сушить и гладить вещь.

## Как это работает

1. Пользователь пишет боту в Telegram и присылает фото бирки.
2. Бэкенд на Rust скачивает фото через Telegram Bot API.
3. Фото вместе с промптом уходит в выбранную модель с поддержкой изображений.
4. Ответ модели форматируется в HTML, поддерживаемый Telegram (`<b>`, `<i>`, `<code>`),
   и отправляется обратно пользователю тем же сообщением в чате.

Никакого отдельного приложения или интерфейса устанавливать не нужно — всё происходит
в обычной переписке с ботом.

## Архитектура

| Модуль | Назначение |
|---|---|
| `main.rs` | Точка входа: читает конфигурацию из `.env`, поднимает бота и API-сервер |
| `bot_logic.rs` | Обработка сообщений Telegram: приём фото, скачивание, формирование и отправка ответа |
| `providers.rs` | Провайдер-агностичный слой доступа к ИИ (см. ниже) |
| `api_logic.rs` | HTTP API (`axum`) на `/api/analyze` — задел под будущий Telegram Mini App |

### Поддерживаемые провайдеры ИИ

Слой `providers.rs` абстрагирован от конкретного сервиса — провайдер задаётся
конфигурацией, без изменений кода:

- **openai_compatible** — любой сервис с OpenAI-совместимым API: сам OpenAI, Groq,
  OpenRouter, DeepSeek, локальные модели (Ollama, LM Studio) и т.д. Адрес сервиса
  настраивается через `base_url`.
- **anthropic** — Claude API.
- **gemini** — Google Gemini API. Поскольку прямой доступ к нему заблокирован в
  некоторых регионах, запросы идут не напрямую, а через прокси на Google Apps
  Script (исполняется на инфраструктуре Google, блокировок не видит). Код прокси
  лежит в `laundry-ai-apps-script/Code.gs`.

## Настройка

Создайте `.env` в корне бэкенда:

```
TELOXIDE_TOKEN=токен_бота_от_BotFather

AI_PROVIDER_KIND=openai_compatible   # openai_compatible | anthropic | gemini
AI_API_KEY=ключ_или_секрет_прокси
AI_MODEL=gpt-4o-mini
AI_BASE_URL=                          # опционально; обязательно для gemini (адрес GAS-прокси)
```

Для `gemini` значения `AI_API_KEY` и `AI_BASE_URL` относятся не к самому Gemini API,
а к прокси на Apps Script — настоящий ключ Gemini хранится только в Script
Properties самого GAS-проекта и наружу не передаётся. Пример GAS скрипта представлен в `GAS/`.  Настройка прокси описана в
`laundry-ai-apps-script/README` (Script Properties: `GEMINI_API_KEY`,
`GEMINI_MODEL`, `PROXY_SECRET`).

## Запуск

```bash
cargo run
```

Бот поднимается через long polling, API-сервер — на `:8080`.

## Безопасность

- Произвольный `AI_BASE_URL` проверяется перед каждым запросом (только `https`,
  резолвинг хоста с отсечением приватных/локальных адресов) — защита от SSRF через
  пользовательский адрес сервиса.
- Размер входящего изображения ограничен на уровне провайдера и на уровне HTTP API.
- Ошибки от внешних сервисов логируются на сервере, но не пробрасываются клиенту
  дословно.

## Статус и планы

Сейчас у всех пользователей общий ключ ИИ из `.env` бэкенда. В планах — Telegram
Mini App с интерфейсом в виде чата, где каждый пользователь сможет подключить
собственный ключ любого поддерживаемого сервиса, не завязываясь на общую квоту.
Черновик фронтенда (React + Vite) лежит в `laundry-ai-tma/`.

## Структура репозитория

```
main.rs                    — точка входа
bot_logic.rs                — логика Telegram-бота
providers.rs                 — слой доступа к ИИ-провайдерам
api_logic.rs                 — HTTP API для будущего Mini App
laundry-ai-apps-script/      — прокси в Gemini на Google Apps Script
laundry-ai-tma/               — черновик Mini App (React + Vite), не завершён
```
